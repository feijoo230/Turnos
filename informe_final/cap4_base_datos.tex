\chapter{Base de Datos}

\section{Diseño general}
El diseño de la base de datos para el Sistema de Turnos Académicos se fundamenta en un modelo relacional robusto, capaz de soportar la complejidad de una institución como la Universidad Nacional de Salta. El objetivo principal es garantizar la integridad referencial y la consistencia de las reservas, evitando solapamientos y asegurando que cada turno esté vinculado correctamente a una dependencia, un trámite y un solicitante.

\section{Modelo Entidad-Relación}
A lo largo del ciclo de desarrollo, la base de datos fue sometida a refactorizaciones para eliminar columnas y tablas redundantes (por ejemplo, los antiguos sistemas de afiliación o los accesos duplicados de administración), optimizando el esquema. 

A continuación se describen las entidades principales identificadas en el esquema \texttt{estructura.sql} y sus interacciones dentro del sistema:

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.95\textwidth]{diagrama_er}
    \caption{Diagrama Entidad-Relación (DER) simplificado del sistema de turnos}
    \label{fig:diagrama_er}
\end{figure}

\begin{itemize}
    \item \textbf{Dependencias y Jerarquía:} La tabla \texttt{dependencias} (vinculada a \texttt{tipos\_dependencias}) es la columna vertebral del sistema. Utiliza el motor \textit{InnoDB} y el patrón \textbf{Nested Set} (\texttt{\_lft}, \texttt{\_rgt}, \texttt{parent\_id}) para realizar consultas jerárquicas indexadas, representando la estructura UNSa $\rightarrow$ Facultad $\rightarrow$ Departamento $\rightarrow$ Observatorio. Asimismo, \texttt{usuarios\_dependencias} asocia operadores con sus unidades asignadas.
    \item \textbf{Catálogo de Servicios y Modalidades:} La tabla \texttt{dependencia\_tramites} define las actividades ofrecidas por cada dependencia y sus reglas operativas (\texttt{tipo\_modalidad}, \texttt{permite\_grupal}, \texttt{min\_personas\_reserva}, \texttt{max\_personas\_reserva}, \texttt{requiere\_institucion}, \texttt{requiere\_nomina}).
    \item \textbf{Agendas, Horarios y Capacidad Operativa:} La tabla \texttt{turnos\_tramites} parametriza los períodos de vigencia (\texttt{fecha\_desde}, \texttt{fecha\_hasta}) y vincula cada servicio con sus bloques en \texttt{turnos\_horarios} (\texttt{hora\_inicio}, \texttt{hora\_fin}, \texttt{duracion\_minutos}, \texttt{cantidad\_turnos}). En paralelo, \texttt{mesas\_habilitadas} controla los puestos activos por dependencia mediante el campo booleano \texttt{activo} (interruptor rápido).
    \item \textbf{Reservas de Turnos y Nóminas de Integrantes:} La tabla \texttt{dependencia\_turnos\_reservas} centraliza las citas solicitadas (\texttt{codigo}, datos del titular, \texttt{fecha}, \texttt{hora}, \texttt{turno\_horario\_id}, \texttt{dependencia\_tramite\_id}, \texttt{estado\_id} hacia \texttt{turnos\_reservas\_estados}, datos de colegios y \texttt{motivo\_cancelacion}). Para delegaciones escolares y grupales, se relaciona uno a muchos con \texttt{dependencia\_turnos\_reservas\_integrantes} (\texttt{reserva\_id}, \texttt{dni}, \texttt{nombre}, \texttt{apellido}).
    \item \textbf{Gestión de Plantillas de Correo Transaccional:} La tabla \texttt{plantillas\_email} almacena las definiciones HTML de las comunicaciones, incluyendo \texttt{clave}, \texttt{nombre}, \texttt{circuito} (\textit{individual} o \textit{colegio}), \texttt{evento} (\textit{solicitud}, \textit{confirmacion}, \textit{cancelacion}), \texttt{asunto}, \texttt{cuerpo\_html}, \texttt{variables\_disponibles} y \texttt{activo}.
    \item \textbf{Calendario y Días No Laborables:} La tabla \texttt{feriados} registra las fechas festivas y asuetos institucionales, permitiendo al motor de reservas excluir dichas jornadas automáticamente.
    \item \textbf{Trámites Digitales y Derivaciones:} Las tablas \texttt{tramites}, \texttt{documentos} y \texttt{pases} registran los expedientes digitales, su documentación adjunta y el historial de derivaciones entre dependencias (\texttt{dependencia\_origen\_id}, \texttt{dependencia\_destino\_id}, \texttt{motivo}).
    \item \textbf{Gestor de Contenidos Institucionales (CMS):} Se integran las tablas \texttt{proyectos\_extension}, \texttt{investigaciones}, \texttt{equipo\_miembros}, \texttt{instalaciones} y \texttt{tipos\_evento}, las cuales estructuran los recursos de divulgación científica exhibidos en el portal público del Observatorio.
\end{itemize}

\section{Diccionario de Datos y Migraciones}
La estructura se ha implementado utilizando las \textbf{Migraciones de Laravel}, lo que permite un control de versiones preciso sobre el esquema de la base de datos y su recreación reproducible en cualquier entorno.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.55\textwidth]{codigo_tree_migrations}
    \caption{Historial versionado de migraciones de la base de datos en \texttt{database/migrations/}}
    \label{fig:tree_migrations}
\end{figure}

Entre los tipos de datos y restricciones más relevantes se destacan:

\begin{itemize}
    \item \textbf{Tipos de Datos Optimistas:} Se utilizan campos de tipo \texttt{tinyint(1)} para estados booleanos (activo/inactivo), optimizando el almacenamiento.
    \item \textbf{Integridad Referencial:} Se han definido restricciones \texttt{ON DELETE CASCADE} en tablas críticas como las de roles y permisos (\texttt{model\_has\_roles}), asegurando que no existan registros huérfanos.
    \item \textbf{Trazabilidad:} Todas las tablas incluyen los campos \texttt{created\_at} y \texttt{updated\_at}, permitiendo auditar cuándo se creó una dependencia o cuándo se modificó el estado de un turno.
\end{itemize}

\section{Optimización y Rendimiento}
Debido a que el sistema puede recibir una alta concurrencia durante periodos de inscripciones o eventos en el Observatorio, se han aplicado las siguientes estrategias:

\begin{itemize}
    \item \textbf{Indexación Estratégica:} Se han creado índices compuestos, como en la tabla \texttt{dependencias} (\texttt{\_lft}, \texttt{\_rgt}, \texttt{parent\_id}), para acelerar la navegación por el árbol académico.
    \item \textbf{Soft Deletes:} Tablas como \texttt{personas} y \texttt{dependencias} implementan \textit{borrado lógico} (\texttt{deleted\_at}), permitiendo recuperar información eliminada accidentalmente y manteniendo el historial de atención.
\end{itemize}
